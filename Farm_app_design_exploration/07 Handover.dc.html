Component inventory

Named so both codebases can consume the same contract. Props are given in the shape a React component would take; the vanilla console reads the same fields off its view model.

Component
Props · states
Status
DeviceFrame
{ profileId, panelW, panelH, dpi, dpWidth, tier, state, size, sheen }
state: off · waking · live · nosignal · ended. size: any rendered width; every dimension derives from it. tier: virtual · physical, and drives which chassis fill and rail set is used.
NEW
DeviceStage
{ device, stream, controls, zoom, fullscreen }
Owns the frame plus the ground shadow and the keyboard-target indicator. Must not unmount between bring-up and session — this is the continuity requirement.
NEW
BringUpSequence
{ steps[], mode, telemetry }
mode: normal · queued · degraded. Each step: { id, label, note, outcome, at } where outcome is pending · waiting · done · failed · skipped. waiting is the state with no observable interior and is the only one that pulses.
NEW
CapabilityMatrix
{ declared[], all[] }
Renders every capability in all; those absent from declared are struck through. Absences are never filtered out — this is enforced by taking both lists rather than one.
EXISTS
StatusPill
{ tone, label, at }
at is required, not optional. A pill without a timestamp does not render — that is how "colour never alone" becomes structural instead of a guideline.
EXISTS
RailControl
{ icon, label, requires, declared, onPress }
If requires is not in declared the control renders dashed and inert with a tooltip naming the missing capability. It cannot be constructed in an enabled state without the capability — the constraint lives in the component.
NEW
ConsequenceDialog
{ title, body, does[], doesNot[], safety, confirmLabel, requireReason }
Both dialog patterns are this one component. doesNot and safety are what make it the pattern worth keeping.
EXISTS
StreamPanel
{ fps, fpsHistory, bitrate, rtt, path }
fpsHistory is the small bar sparkline — last 8 samples. CONFIRM whether history is retained or must be accumulated client-side.
NEW
SubstitutionNotice
{ asked, got, reason, onKeep, onRequeue }
Shown at handover when the allocated device's geometry differs from the requested class. Blocks nothing, dismisses only by choosing.
NEW
CommandPalette
{ groups[], query }
Groups are GO TO and DO, never interleaved. Device results carry a DeviceFrame at 12px width and the free count.
EXISTS
FleetTable
{ devices[], lens, onAction }
lens: capacity · catalogue · live · waiting. One data source, four presentations. Only needed if direction B is chosen.

Where technical terms are still allowed
Session id, WebDriver URL, data-plane URL, package name, ABI, geometry, capability names, log lines, host id, tier. All of them presented as machine text: mono, selectable, in a copy field or a details table. The register itself tells the reader this came from the machine rather than from us — which is why they can stay.

Build order

Sequenced so each stage is shippable on its own and nothing waits on an undecided question.

1
Tokens and type
Land 01 as an evolution of design-tokens.css. Self-host the three families. Add the radius, elevation and motion scales. Nothing visual changes yet except type.
no blockers
2
Icons and primitives
Lucide sprite in, twenty Unicode glyphs out. Then the seven primitives from 06. This is the change that stops the console looking unfinished, and it touches every screen at once.
no blockers
3
DeviceFrame and DeviceStage
The headline job. Build the resolver against the profile table and render it everywhere a device appears — cockpit, catalogue, table rows, palette results. One component, five sizes.
needs profile table fields
4
The copy pass
Every string in the deck above. Cheap, high-visibility, and independent of everything else. Worth shipping before the layout work rather than after.
no blockers
5
The cockpit
Four states from 04, the new StreamPanel, and the capability-driven rail. The stage is already built by stage 3, so this is layout and panels.
stage 3
6
Bring-up choreography
The motion spec. Do it after the cockpit so the frame can transition into a layout that already exists. Each CONFIRM beat ships with its fallback first and its progressive version once the endpoint is verified.
stage 5 · telemetry
7
Fleet, catalogue, substitution
The IA change, once you have chosen. Old routes become redirects and the G shortcuts become lens shortcuts, so nothing a current user knows stops working.
IA decision
8
Light theme
Last, because it needs a pass to remove hardcoded hexes from every component. The values are all specified; the work is mechanical.

Open decisions

Nothing in the package is blocked on these, but each one changes something specific.

Decision
Assumed
What changes if not
Which console is production
Both specced. Tokens as CSS custom properties, components as a contract either can read.
If it is the React console, the inventory becomes the build list directly and the vanilla console gets redirects.
Allocator pinning
Class-only, permanently.
If pinning is possible the picker promises a specific unit, SubstitutionNotice is not needed, and the catalogue can list individual devices.
Snapshot-restore progress
Exists. Step 2's wake glow tracks it.
Glow pulses on the 2.2s loop instead. No layout change.
Install byte progress
Exists. The build tile's travel maps to bytes.
Tile waits outside the frame and lands on confirmation. The queued panel in 04 becomes the whole design.
Queue position and ETA
Exists. "Second in line, about 12 minutes."
Copy drops to "the farm hands over when a lease ends". Position without ETA still works; neither would leave only "you are in line".
Stream negotiation sub-states
Exists. Shown as machine text under step 4.
Step 4 shows only its outcome. Nothing else moves.
Catalogue prose
A description column on the profile table.
One-column migration, or the catalogue shows specs without prose — weaker as a sales surface, still useful for choosing a screen size.
Glass sheen over real pixels
On at .07, with a settings toggle to zero.
Off by default costs most of the glass read. The toggle matters either way for visual-comparison work.
One thing that is not open
The frames stay MFARM's. No other manufacturer's badge, trade dress, camera-island layout or model name, on any tier — that is ADR-0017 and it is also what separates a premium product from a counterfeit one on a commercial surface. The physical SM-S918B is the sole exception and only because it genuinely is that device: drawing its real proportions is accurate representation, and it is labelled with its own model number rather than an MFARM tier.
