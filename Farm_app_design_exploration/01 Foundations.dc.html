The one idea

The console is a neutral desk. The device is the warm object sitting on it. Every surface in the UI stays chromatically quiet so that the phone — the only thing with material, temperature and depth — is the thing your eye lands on. That is what buys the premium read without a single gradient in the chrome.

Quiet chrome
Surfaces carry no chroma. One accent, used only for the primary action and selection. Semantic colour never appears except to describe a real state.
Depth is a state
Elevation is not styling. A device's shadow is shallow until its data plane attaches, and lands when it does. A panel lifts when it becomes interactive. Nothing floats decoratively.
Register separates prose from machine
Anything the farm generated — ids, URLs, ABIs, log lines — is mono, selectable, copyable. Anything MFARM wrote to a human is sans. The reader always knows which they are looking at.

Colour

Dark is primary. Light is a true peer, not a filter: it re-derives every value against a warm off-white ground so that hairlines stay visible and the accent keeps its 4.5:1 on white. Semantic colours darken in light theme to hold contrast — they are never the same hex in both.

The rule that outranks the palette
Colour never carries meaning alone. Every state in the markup is a dot plus a label plus a timestamp. If you can delete the colour and the sentence still tells you what happened and when, the state is built correctly. This is why the light theme can re-derive every hex without any state becoming ambiguous.

--e-device · the one expensive shadow
The device gets a three-layer shadow plus a contact ellipse, because it is the only object in the product that should read as physical. It is also the only shadow that changes with state: shallow while the device is off or queued, full once the data plane attaches.
--e-device-flat: 0 1px 0 rgba(255,240,225,.2) inset, 0 4px 10px -4px rgba(0,0,0,.5);
--e-device: 0 1px 0 rgba(255,240,225,.2) inset, 0 2px 3px rgba(0,0,0,.7),
               0 20px 36px -8px rgba(0,0,0,.78), 0 50px 90px -22px rgba(0,0,0,.9);
In light theme the inset highlight stays warm-white but the cast layers lose opacity roughly by half — a phone on a bright desk has a shorter shadow.

Nothing else in the console gets a shadow. No shadow is ever animated over the live stage: rendering is software and frame rate is the proof the session is healthy, so compositing cost near the panel is a bug, not a style choice.

The only loop in the system: a live dot, and a step waiting on something unobservable
Legitimate motion
A step turning from pending to done when its event lands. A shadow deepening on attach. Real pixels fading up when the stream negotiates. A percentage moving because a percentage arrived. A dot pulsing to say a connection is alive right now.
Motion that would be a lie
A bar that fills on a timer. A checkmark that lands before the worker confirms. A spinner on an action whose only reportable states are queued and finished. An ETA the allocator never gave us. Any of these turns the console's core asset into a liability.
Disabling it
The existing data-liveness="still" setting and prefers-reduced-motion both resolve to the same thing: --mf-pulse: 0s and every duration to 1ms. Nothing is conveyed by motion alone, so the console with all motion removed loses no information — a step that was pulsing amber still reads waiting on the worker's next heartbeat in words.

Open assumptions

Recorded here rather than buried, because a developer will hit them.

ASSUMPTION
Allocation is class-only. The picker promises a class, not a unit, and the handover moment names what you actually got. If pinning becomes possible the picker can promise a model and the substitution flow disappears — say the word and I will respec it.
CONFIRM ENDPOINT
Five telemetry sources. Snapshot-restore progress, install byte progress, stream negotiation sub-states, queue position and ETA, and worker heartbeat timing. Each one is used in the bring-up design and each is marked at the point of use. Where one turns out not to exist, that beat degrades to the honest waiting state rather than the panel breaking.
NET-NEW
Light theme. Every value above is specified, but no component in either console currently reads a theme. Expect a pass to remove hardcoded hexes before it can be switched on.
FONTS
This document loads the three families from a font CDN so you can read it. Production must self-host the same woff2 files, which the codebase already does. No design here depends on a weight outside 400–700.
