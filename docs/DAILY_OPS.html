MFARM · lab operations

Lab day card

Start the box, do the work, stop the meter. Every command you need for a session on the Cuttlefish lab VM, in the order a day actually runs.

project mfarm-lab instance mfarm-lab zone asia-south1-c repo on VM ~/mfarm
The meter — the one thing worth memorising
~₹65 / hour Instance RUNNING. Charged per second, whether it is building or idle.
~₹42 / day Instance TERMINATED. Compute is free; the 150 GB disk still bills.
₹0 Instance and disk DELETED. The only state that costs nothing.

Stopping is not deleting. An overnight stop costs pocket change; a forgotten running box costs about ₹1,600 a day.

01

Start

meter starts

All of this runs in Cloud Shell — the >_ icon in the Google Cloud console, not on your Mac and not on the VM.

Cloud Shell
gcloud config set project mfarm-lab
gcloud compute instances list
gcloud compute instances start mfarm-lab --zone=asia-south1-c
Set the project every session. Cloud Shell VMs are recycled when idle and lose core/project. You can tell at a glance: the prompt reads (mfarm-lab)$ when it is set and plain $ when it is not.

Wait for RUNNING, then give sshd about 30 seconds before connecting.

Cloud Shell
gcloud compute ssh mfarm-lab --zone=asia-south1-c
The external IP changes every start. It is ephemeral and released on stop, so never write it down or hard-code it anywhere. Always reach the box by instance name.
02

Work

~₹65 / hour

Run everything inside tmux. Your SSH is a browser tab: if it drops, closes, or idles out, anything running in it dies with it. tmux keeps the work alive on the VM.

on the VM — pick one
tmux new -s mfarm      # first session after a boot
tmux attach -t mfarm   # it already exists ("duplicate session")

Ctrl-b then d detaches and leaves it running. Ctrl-b then c opens a second window. A tmux session does not survive a reboot — after one, always new.

Pull and run the bootstrap

on the VM
cd ~/mfarm && git pull
./spikes/bootstrap_cuttlefish.sh

It resumes from ~/.mfarm_bootstrap, so re-running is always safe and never redoes finished work.

Check the device

on the VM
adb devices
adb -s 0.0.0.0:6520 shell getprop sys.boot_completed
adb -s 0.0.0.0:6520 shell getprop ro.build.version.release
cvd stop

Logs, when something fails

on the VM
tail -40 /tmp/cf_build.log      # package build
tail -40 /tmp/cf_fetch.log      # image download
tail -40 /tmp/cf_start.log      # device boot
head -c 800 /tmp/cf_buildlist.json  # build API response

Stepping away mid-run

Open a second tmux window and leave this watching. It powers the box off the moment the script finishes — success or failure — so a long download does not bill all night.

on the VM — second tmux window
while pgrep -f '[b]ootstrap_cuttlefish.sh' >/dev/null; do sleep 60; done
cp /tmp/cf_*.log ~/ 2>/dev/null
sudo poweroff

The brackets in [b]ootstrap stop pgrep matching its own command line, which would loop forever. The cp saves the logs first, because /tmp is not guaranteed to survive a boot.

03

Stop

meter drops to disk only

Simplest and most reliable, from inside the VM. No permissions needed, works every time.

on the VM
sudo poweroff
Do not run gcloud compute instances stop on the VM. A VM authenticates as its own service account, which cannot stop instances — you get ACCESS_TOKEN_SCOPE_INSUFFICIENT. Use sudo poweroff there, or run gcloud from Cloud Shell where you are authenticated as yourself.
Cloud Shell — confirm, or stop from here
gcloud compute instances list
gcloud compute instances stop mfarm-lab --zone=asia-south1-c

You want STATUS: TERMINATED. That is the meter down to disk only.

Finished for good

₹0

Deleting the instance is not enough on its own — confirm no disk survived it.

Cloud Shell
gcloud compute instances delete mfarm-lab --zone=asia-south1-c --quiet
gcloud compute disks list
rm -f ~/.netrc          # on the VM first, if it still exists
gh auth logout          # on the VM first

Lookup

When it breaks

Keyed to what the terminal actually prints, so you can search this page for the error text.

The required property [project] is not currently set
Cloud Shell was recycled and lost its config. The prompt lost its (mfarm-lab) too.
gcloud config set project mfarm-lab
PERMISSION_DENIED … ACCESS_TOKEN_SCOPE_INSUFFICIENT
You ran a gcloud command on the VM. It authenticates as its own service account, which has no permission to manage instances.
Use sudo poweroff on the VM, or run the gcloud command from Cloud Shell.
ssh: connect to host … port 22: Connection refused
The machine is up and reachable — refused means the network path works — but sshd has not started yet.
Wait 30–60 seconds and retry. Still failing after ~3 minutes: gcloud compute instances get-serial-port-output mfarm-lab --zone=asia-south1-c | tail -40
External IP address was not found; defaulting to using IAP tunneling
Error while connecting [4003: 'failed to connect to backend']
No external IP means the instance is not running at all. A stopped instance has none.
gcloud compute instances start mfarm-lab --zone=asia-south1-c
duplicate session: mfarm
The tmux session is still alive from earlier, which also tells you the VM never rebooted.
tmux attach -t mfarm — or tmux kill-session -t mfarm first for a genuinely fresh one.
Failed to download file: File Not Found
The pinned build's artifacts were garbage-collected, or a build id was used whose image never finished uploading. Not a naming or network problem.
Read a fresh green build id off the CI grid — confirm its artifacts list an -img- zip — then CF_BUILD_ID=<id> ./spikes/bootstrap_cuttlefish.sh
403 Rate limit exceeded for legacy API. You must migrate to Build API v4
Expected, and not fixable by waiting. Google retired anonymous access to the build API's listing endpoints. Single-artifact downloads still work, so a known build fetches fine — only discovery is gone.
Get the build id from the CI grid in a browser. See known issue 10 in HANDOFF.md.
429 Too Many Requests (during a Cuttlefish build)
GitHub rate-limits per source IP and cloud IP ranges are shared, so this is other people's traffic. Should no longer occur — the script installs prebuilt packages from Artifact Registry instead of building.
If you see it, you are on the source-build fallback. Check why the registry install failed rather than waiting it out.
